# AI500 Clone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a shadow-only AI500-compatible scorer that ranks Bybit perpetual candidates with an aggregate 0–100 score while preserving directional scores and training observations.

**Architecture:** Add a focused `ai500` Go package with immutable feature snapshots, a provider-neutral LLM scoring interface, strict score validation, and append-only observation persistence. Adapt validated observations into `parity.CandidateSnapshot`; keep execution behind the existing `parity.NewShadowExecution()` path and never change the live VergeX/9Router services.

**Tech Stack:** Go, standard library JSON/HTTP/time, existing `nofx/market`, `nofx/parity`, GORM-backed project store only where existing store interfaces are required, Go test.

## Global Constraints

- Shadow mode only: no private Bybit order endpoint and no live execution switch.
- The LLM receives normalized numeric features, not raw exchange credentials or raw prompts.
- Scores and confidence are finite numbers in the inclusive range 0–100.
- Missing, stale, or invalid market data produces an unavailable score; never fabricate a value.
- Logs contain IDs, counts, versions, timings, and error codes, never API keys, authorization headers, or full prompts.
- Every new production function has a focused test; run `gofmt` and `go test ./...` after each task.
- Do not modify the existing VergeX/9Router/CLI Proxy services.

- [ ] **Step 3: Implement the contract**

```go
type Regime string

const (
    RegimeBullish Regime = "bullish"
    RegimeBearish Regime = "bearish"
    RegimeNeutral Regime = "neutral"
)

type ScoreObservation struct {
    ID              string
    Symbol          string
    Score           float64
    LongScore       float64
```
